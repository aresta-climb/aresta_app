## Why

Currently, the app bundle generated by CI (or locally) using `sync_preload.dart` is getting poisoned when only a thumbnail is updated on the server. The script checks the croqui's hash (`checksumSha256Croqui`) instead of the thumbnail's hash (`checksumSha256Thumbnail`) to decide if the thumbnail needs to be downloaded. Consequently, the script writes the updated `indice.binarypb` (with the new thumbnail hash) but keeps the old `thumbnail.webp`.

When users install or update the app, `sync_service` compares the local hash (from the bundled index) with the server hash. Since both have the new hash, it assumes the image is already up-to-date and never downloads the new thumbnail, leaving users stuck with the old image.

## What Changes

- Modify `tool/sync_preload.dart` to extract and store `checksumSha256Thumbnail` in a dedicated `oldThumbnailHashes` map.
- Update the comparison logic to check `oldThumbnailHashes[cragId] != resumo.checksumSha256Thumbnail` when deciding whether to download a new thumbnail.
- Add a unit test to verify that thumbnail caching logic correctly invalidates and downloads a new thumbnail when only its hash changes.
